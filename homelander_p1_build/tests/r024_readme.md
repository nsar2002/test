# R024 — bounded read-only Lua-global key/type census (NOT a player-handle fix)

The authentic original v003 BOOT/F4/F9 evidence has PLAYER=nil and seven hardcoded GOH name lookup routes returning nil. No validated player GOH has been obtained. The external `Prototype1-Lua-Tool/src/sdk/lua_globals.hpp` source actually documents a curated list from `prototype2engine.dll` (Prototype **2**), so it is not a trustworthy API inventory for the user's exact Prototype 1 DLL. R023 byte-pinned source research has not established a safe direct player getter.

R024 adds a **standalone, optional, SOURCE-ONLY** Lua5.1 diagnostic intended for a future, already-authorized live Lua execution context, NOT for automatic original R007 bootstrap. It enumerates the existing `_G` table once with the Lua built-in `next` and logs only matching global key names and `type(value)` for names containing player/alex/avatar/character/hero/actor/goh (case-insensitive). Each key is an ASCII Lua identifier of at most 72 bytes. Up to 64 names are emitted sorted by key and the full match count is printed; the exact hidden names beyond the cap are not enumerated. It explicitly logs the `PLAYER` global's type even when nil.

**Safety boundary:** No userdata/table values, pointer address or raw game IDs are logged or `tostring`-ed. No metatable traversal, registry dump, arbitrary GOH dereference, speculative index conversion, game getter/setter, nested global enumeration, debug hook, or global assignment occurs. The only intended side-effect is writing bounded diagnostic lines through the already available HL_Log or print function. An observed global named `PlayerGOH` with type `userdata` would be merely a candidate, NEVER an independently verified player; external native verification and exact provenance are required before any gameplay mutation.

This candidate is NOT included in any official R007 ZIP/stage or the R018 assembled 22 Lua runtime. It cannot be run through the original frozen manager without installing a separately reviewed instrumented candidate, and it should NOT prompt the user/Gemini to add a second ASI, overwrite original v003, or launch unauthorized debug injection. It is suitable only if an already-authorized Lua 5.1 interpreter in the genuine game is independently available. Otherwise retain it as dormant research until after genuine evidence or a separately approved experimental build can be prepared. User's active v003 remains failed/unpromoted; v004+ installation remains blocked.

CI independently tests the script in Lua 5.1 with `newproxy()` userdata that throws on stringification/index, engine API tripwires, positive matching keys, absent PLAYER, >64 matching keys, and intact candidate values. These tests cannot establish what globals actually exist in the user's game.
