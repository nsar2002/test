# R013 — F17 irreversible damage transaction reservation, source only

The original staged F17 called go_ApplyDamage before setting HOMELANDER_DAMAGE_ONESHOT_PASSED. An engine bridge callback can synchronously invoke F17 again while the original is inside pcall(go_ApplyDamage), causing TWO damage calls even though F17 was described as one-shot. The original also published last-target/last-hit success metadata before the native call, and when a void native mutation returned by throwing after an effect, the old guard treated it as a retryable failure; a second attempt could duplicate damage. The original did not re-check player and native/Lua dynamic F16 stability after reentrant LOS/target getters immediately before mutation.

New isolated heatvision_damage_gate_v011_reserved_DORMANT.lua uses independent monotonic F17 attempt generations, rejects callbacks replaced during camera/LOS/target lookup, revalidates player and target and live Lua/native F16 stability immediately before damage, then sets HOMELANDER_DAMAGE_ONESHOT_RESERVED=true BEFORE calling the native damage API. Nested/retried F17 from the native callback is refused. If the void binding raises after unknown native effects, it returns false WITHOUT minting F18 success metadata, but keeps the irreversible reservation to prevent another damage call. Only an unambiguously returned native call records F17 LAST_* and HOMELANDER_DAMAGE_ONESHOT_PASSED=true. This is a conservative 'at most one submission per Lua-state lifecycle' rule, not a guarantee the engine actually applied damage on a void return. Reloading/restarting an entire Lua state may reset local/global guards, and a separate native enforcement mechanism would be required for a cross-reload guarantee.

New deterministic real-source Lua5.1 engine mock reproduces original two native F17 submissions via reentrant native callback, then validates new exactly one submission, post-side-effect exception consumed without success/F18 proof or retry, player switched during LOS blocks damage, F16 proof revoked during target getter blocks damage, and normal positive one-shot still reaches prior staged F18 success boundary. Existing 22-native-script assembler maps EIGHT paired protected files F9/F10/F11/F12/F14/F15/F16/F17 into original native path names; all original R007 game stages, manager, native C++, user game files remain unmodified. Real game F17 is NOT authorized until original R007 v003 BOOT/F4/F9 and every intermediate sequential real-game stage have proved their gates; this source candidate is NOT installable.
