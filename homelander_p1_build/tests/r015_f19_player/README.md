# R015 — F19 continuity must be owned by the same player that submitted F17

Original F19 continuity source stores only the target GOH. After original player A completes F17/F18, player A can be replaced by player B while the same NPC remains visible. Old F19 continues counting B's line-of-sight samples and can publish F19 continuity PASS based on mixed A+B frames, even though the damage and impact originated from A. The original code also retains the previous F19 PASS when a later F19 activation fails, allowing stale downstream F20 proof.

A paired guarded F17 source additionally records HOMELANDER_DAMAGE_LAST_PLAYER only on a successful native one-shot and never on an ambiguous/failed submission. New guarded F19 source binds S.player to that original successful F17 player; a new F19 attempt invalidates any prior F19 pass before callbacks, and activation refuses different original/current players. During each tick, the originating player, F17 target and F18 submitted proof must remain unchanged even after camera/health/LOS callbacks; reentrant disable/toggle changes S.generation and prevents superseded tick publication. A positive F19 receipt includes HOMELANDER_TARGET_CONTINUITY_PLAYER for downstream guarded F20 use. This is within the same Lua state; it cannot authenticate a forged GOH across runtime sessions.

An actual-source mock runs guarded F17 -> guarded F18 then reproduces original F19 mixing A and B for the same NPC, asserts guarded F19 rejects player B without publishing F20 continuity, validates A-only 15-frame success, rejects stale F19 proof after a newly failed attempt and activation-time player switch inside a health callback. All previous R009–R014 source tests and 22 native path/unchanged C++ scratch build remain in full CI. Assembled source-only bundle contains TEN atomic protected modules: F9–F12, F14–F19 (F17 and F19 must be paired), plus the remaining native Lua sources unchanged.
